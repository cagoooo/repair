### 演練方法與其限制（重要）

本輪為**離線演練**：把 PDF 文字層轉成與 Google Vision `textAnnotations` 相同的詞塊格式（左上原點像素座標），再餵進專案**正式的**演算法執行：

`parseVisionAnnotations()` → `convertPixelToPercent()` → `mergeRoomsByCode()` → `buildMapReadinessReport()`

- ✅ 有效驗證：真實 115 版面幾何下的**編號辨識、直排編號還原、名稱聚合門檻、座標換算、合併與發布前檢查**。
- ⚠️ 無法驗證：真實 Vision 的**字元誤認**與**信心分數**（文字層是完美文字、且無 confidence 欄位）。
- ⚠️ 無法驗證：與正式 Firestore 現況的**新舊差異、教室總數變動、歷史報修失聯**（需線上資料）。

也就是說：本報告的「漏判／誤判」是針對**版面與聚合邏輯**，不等於線上真實 OCR 的最終數字。線上仍須跑一次真實 OCR 演練。

樣本已存為可重複使用的回歸 fixture：[tests/fixtures/map-115-textlayer.json](../tests/fixtures/map-115-textlayer.json)，並由 [visionService.test.js](../src/services/visionService.test.js) 的「115 學年度實圖文字層回歸」鎖住行為。

## 三、發現的問題（依嚴重度）

### 🔴 問題 1｜班級名稱丟失班號，5 間教室會同名（阻擋發布）

`C102`～`C106` 期望「一年1班」～「一年5班」，實際全部只得到「**一年**」。同樣情形涵蓋二、三、四、五、六年級與課照班：

| 期望 | 實際 | 受影響 |
| --- | --- | --- |
| 一年1班～一年5班 | 一年 | C102–C106 |
| 二年1班～二年5班 | 二年 | C108、C109、C111、C112、C113 |
| 三年1班～三年5班 | 三年 | C120–C124 |
| 四年1班～四年5班 | 四年 | C128–C130、C132、C133 |
| 五年1班～五年5班 | 五年 | C220、C221、C223–C225 |
| 六年1班～六年6班 | 六年 | C307–C310、C313、C314 |
| 課照班1A／1B／2A／2B | 課照班 | C107、C114、C234、C233 |
| 魚寶屋課照班6B | 魚寶屋 | C217 |
| 英語一課照班3B | 英語一 | C229 |
| 情境教室課照班5A | 情境教室課照班 | C218 |

**後果**：同年級 5 間教室在地圖與報修單上顯示完全相同的名稱，使用者無法分辨要報修哪一間，且管理員需逐間手動補回班號（至少 40 間）。

**根因**：[visionService.js:106](../src/services/visionService.js#L106) 的水平對齊守門條件

```js
if (dx > anchor.pixelBounds.width * 0.5) return false;
```

「1」「班」這兩個詞塊與編號同一行但偏右，`dx` 超過編號寬度的一半就被判為別人的名稱而丟棄。此限制原本是為了修掉「檔案室六年」的跨房間誤併，屬於刻意的取捨，但在 115 版面上代價過大。

### 🔴 問題 2｜多行名稱只取到第一行（阻擋發布）

| 期望 | 實際 |
| --- | --- |
| 視聽器材室 | 視聽器 |
| 智慧教室 | 智慧 |
| 韻律教室 | 韻律 |
| 人事會計 | 人事 |
| 特色餐教室 | 特色餐 |
| 電腦教室（C212、C213） | 電腦 |
| 學習中心（C116、C118） | 學習 |
| 研習中心 | 研習 |
| 知動教室 | 知動 |

**根因**：同一函式的 `thresholdY = anchor.pixelBounds.height * 1.5`，往下只找 1.5 倍字高，第二行以下的名稱被排除。

### 🟠 問題 3｜兩間教室名稱完全遺失

`C306 桌球練習室`、`C210 大辦公室` 名稱**整段丟失**（結果為空字串）。這兩個名稱較長、起點明顯偏左於編號，被問題 1 的 `dx` 守門條件整條擋掉。

好消息：兩者會進入人工確認佇列的 `missing_name` 類別，不會靜默發布。

### 🟡 問題 4｜圖上本來就沒有名稱的 19 個編號

- 16 個廁所／樓梯編號（W101–W302、S104–S107）：圖上僅有編號，屬正常。
- **C115、C215、C311 這 3 個編號在圖上有框有編號但沒有任何名稱文字** → 需向教務處確認實際用途後人工補上。

### 🟡 問題 5｜S 系列樓梯被歸類為 classroom

`S104`～`S107` 因無名稱且開頭非 `W`，分類落到 `classroom`（W 系列則正確歸為 `utility`）。建議把 `S` 前綴也納入 `utility`。

### 🟡 問題 6｜所有教室框都只有「文字大小」，100 間都需人工校正

OCR 產生的 `bounds` 是文字外框，平均僅約 3%×1%（最小 W104 為 2.69%×0.95%）。`mergeRoomsByCode` 以 `{...existing, ...incoming}` 合併，**incoming 的 bounds 會覆蓋舊配置已校正好的框**。這對換新圖是合理設計（舊座標本就不適用新版面），但意味著：

- 換版時 100 間教室的點擊範圍都需在「位置校正」步驟重新調整。
- 發布前檢查的「異常過小」門檻是 0.5%，而這些框是 0.95%～1%，**不會觸發任何警告**，管理員可能沒意識到框都縮成標籤大小。

**已於 v0.14.0 解決**：差異確認畫面新增「沿用現有教室框位置，只更新名稱與分類」選項（預設勾選）。配置未實際變動的學年度只需更新名稱，不必重新校正。以 115 實圖模擬 101 間換版實測，勾選後差異統計由「移動 100」降為「移動 0」，名稱更新照常生效。配置真的有搬動時取消勾選即可回到原本行為。

### 🟡 問題 7｜新舊圖比例可能觸發硬性阻擋

新圖為 A4 直式，比例 **0.707**。若 114 學年度正式配置圖是橫式（比例 > 1），`buildMapReadinessReport` 的 `image-ratio-critical` 會判定差異 > 15% 並**以 error 阻擋發布**，必須重新辨識並逐區校正。上線前請先確認線上現行圖片比例。

### 修正內容

原本的兩道守門條件被移除，改成以版面幾何推算歸屬：

1. **教室欄位推算**：由同一橫列相鄰編號的間距，算出每個編號的欄位左右界（邊界落在兩個編號的中線）。
2. **名稱指派**：文字塊以**左緣**落在哪個欄位決定歸屬（中文名稱常被切成「一年」＋「1」＋「班」，尾段中心可能越過中線但左緣仍在本欄）；並限定必須位於編號**下方** `0.8`～`3.2` 倍字高之間。
3. **同行右側例外**：保留一個受限分支，接受緊鄰編號右側的同行文字，以應付真實 Vision 可能把「C112 二年甲班」切在同一行的情形。
4. **S 系列分類**：`S104`～`S107` 樓梯間改與 W 系列一致歸為 `utility`（問題 5）。
5. **分類優先序**：改為「公共設施 → 特殊教室 → 行政辦公 → 一般教室」。原本先比對「室」再比對「器材」，導致「視聽器材室」被歸成 `office`；調整後 `special` 由 5 間增為 6 間、`office` 由 24 間減為 23 間，真正的行政空間（總務處、校史室等）仍為 `office`。

### 已驗證不再發生的誤併

- `C211` 得到「檔案室」且**不含**右側 `C307` 的「六年」（舊版經典誤併「檔案室六年」未復發）。
- 無編號區域「川堂」「交材室」**不會**被併入任何教室（「川堂」剛好落在 `C106`／`C107` 中線上，靠「必須位於編號下方」的下限擋掉）。
- 東側密集區 25 間名稱全對且互不吞併。

回歸測試已從 60 項增加到 64 項，新增 4 項鎖住班號保留、多行名稱、不誤併與 W／S 分類。
